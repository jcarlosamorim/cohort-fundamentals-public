Fases 1-3 Diagnóstico completo (em paralelo)
Três Especialistas Avaliam
3 Peritos em Paralelo
Cada um avalia sua área
  • Engenheiro Estrutural: Fundações, paredes, laje, rachaduras
  • Encanador/Eletricista: Tubulações, fiação, quadro elétrico
  • Arquiteto de Interiores: Layout, acabamentos, iluminação
Três Agentes Coletam Dados
3 Agentes em Paralelo
Cada um documenta sua área
  • @architect → *document-project
    Stack, estrutura, dependências, débitos de sistema
  • @data-engineer → *db-schema-audit
    Schema, RLS, índices, performance, segurança
  • @ux-design-expert → *create-front-end-spec
    Componentes, design system, a11y, responsividade
Fase 4 Consolidar num laudo único
Laudo Unificado
Engenheiro Principal
Junta os 3 laudos num documento só
  • Consolida achados de todos os especialistas
  • Marca o que cada um precisa confirmar
  • Cria lista preliminar de problemas e custos
Consolidação Inicial
@architect
Consolida DRAFT com todos os débitos
  • Junta débitos de sistema, database e frontend
  • Marca seções pendentes de validação
  • Cria matriz preliminar de priorização
→ technical-debt-DRAFT.md
Fases 5-7 Validação + Quality Gate
Validação + Vistoria
Especialistas + Fiscal
Cada um valida sua parte, fiscal aprova
  • Encanador: Confirma problemas hidráulicos, ajusta custos
  • Designer: Confirma problemas estéticos, sugere soluções
  • Fiscal Municipal: Vistoria geral → APROVADO ou REFAZER
Validação + QA Gate
Especialistas + @qa
Cada agente valida sua seção
  • @data-engineer: Valida débitos de DB, estima horas, prioriza
  • @ux-design-expert: Valida débitos de UX, sugere soluções
  • @qa: Quality Gate → APPROVED ou NEEDS WORK
⟲ Se NEEDS WORK → volta pra Fase 4
Fase 8 Laudo final aprovado
Laudo Final
Engenheiro Principal
Incorpora todas as correções
  • Incorpora ajustes de cada especialista
  • Recalcula custos e prazos finais
  • Documento completo, pronto para orçar
Assessment Final
@architect
Consolida assessment definitivo
  • Incorpora validações dos especialistas
  • Recalcula prioridades com inputs de todos
  • Define ordem final de resolução
→ technical-debt-assessment.md
Fase 9 Orçamento pro dono
Orçamento da Reforma
Orçamentista
Apresenta custos ao proprietário
  • Custo de resolver vs custo de não resolver
  • Timeline fase por fase
  • ROI da reforma (valorização do imóvel)
Relatório Executivo
@analyst
Relatório de awareness para stakeholders
  • Custos claros: resolver vs não resolver (em R$)
  • Impacto no negócio (performance, segurança, UX)
  • Timeline recomendado + ROI estimado
→ TECHNICAL-DEBT-REPORT.md
Fase 10 Plano de obra
Plano de Execução
Mestre de Obras
Cronograma, equipe, fases
  • Quick wins primeiro (pintura, acabamento)
  • Fundação depois (estrutural, elétrica)
  • Otimização por último (paisagismo, detalhes)
Epic + Stories
@pm
Cria epic e stories priorizadas
  • *brownfield-create-epic → Epic de resolução
  • *brownfield-create-story → Story por débito
  • Pronto para @dev iniciar implementação
→ epic-*.md + story-*.md
Quando Usar

Discovery vs Ir Direto pro Workflow

Nem todo projeto precisa de discovery. Veja quando usar cada abordagem.

Usar Discovery

  • → Migração de Lovable / v0.dev
  • → Codebase legado sem documentação
  • → Due diligence técnica antes de investir
  • → Planejamento de modernização completa
  • → Onboarding em projeto desconhecido

Pular pro Workflow

  • → Projeto já tem docs → brownfield-fullstack
  • → Só backend → brownfield-service
  • → Só frontend → brownfield-ui
  • → Bug fix rápido → brownfield-create-story
  • → Feature nova → brownfield-create-epic

O Fluxo Discovery de Ponta a Ponta

10 fases. 6 agentes. Cada um com papel definido.

brownfield-discovery.yaml — workflow
# Workflow: brownfield-discovery v2.0
# "Diagnostica. Valida. Planeja. Só então executa."

# ═══ FASES 1-3: COLETA DE DADOS (paralelo) ═══

@architect → *document-project
└─ docs/architecture/system-architecture.md

@data-engineer → *db-schema-audit + *security-audit
├─ supabase/docs/SCHEMA.md
└─ supabase/docs/DB-AUDIT.md

@ux-design-expert → *create-front-end-spec
└─ docs/frontend/frontend-spec.md

# ═══ FASE 4: CONSOLIDAÇÃO ═══

@architect → consolida DRAFT
└─ docs/prd/technical-debt-DRAFT.md

# ═══ FASES 5-7: VALIDAÇÃO DOS ESPECIALISTAS ═══

@data-engineer → valida seção DB
└─ docs/reviews/db-specialist-review.md

@ux-design-expert → valida seção UX
└─ docs/reviews/ux-specialist-review.md

@qa → Quality Gate
├─ ✓ APPROVED → segue pra Fase 8
└─ ✗ NEEDS WORK → volta pra Fase 4

# ═══ FASES 8-9: REPORTS FINAIS ═══

@architect → Assessment Final
└─ docs/prd/technical-debt-assessment.md

@analyst → Relatório Executivo
└─ docs/reports/TECHNICAL-DEBT-REPORT.md

# ═══ FASE 10: PLANNING ═══

@pm → *brownfield-create-epic
└─ docs/stories/epic-technical-debt.md

@pm → *brownfield-create-story (repete por débito)
├─ docs/stories/story-1.1-fix-security-rls.md
├─ docs/stories/story-1.2-add-missing-indexes.md
└─ docs/stories/story-1.3-implement-design-system.md

Discovery completo. Pronto para @dev iniciar implementação.

Regras de Ouro do Discovery

de mexer

Múltiplos olhares

Insight do Bloco

O discovery transforma caos em plano de ação.
Projetos migrados de Lovable, v0.dev ou legados parecem impossíveis de melhorar. O brownfield-discovery usa 6 agentes especializados em 10 fases para produzir um relatório executivo com custos, riscos e ROI. O dono do produto recebe um documento de decisão, não uma lista de problemas técnicos.

Mao na Massa

Exercicio: Diagnostique um Projeto Real

Aplique o raciocinio do Brownfield Discovery a um projeto que voce ja tem. Pode ser um site, app, planilha, processo — qualquer coisa.

Mini-Discovery em 4 Perguntas

Escolha 1 projeto que voce ja tem e responda as 4 perguntas abaixo

Fase 1 @architect — Sistema & Stack

Qual e a "arquitetura" atual do seu projeto?
Como as partes se conectam? Quais ferramentas, plataformas ou servicos voce usa? Existe documentacao?

Fase 2 @data-engineer — Dados

Onde estao os dados?
Planilha? Banco de dados? Tudo na cabeca? Os dados estao seguros? Tem backup?

Fase 3 @ux-design-expert — Interface

O que o usuario final ve?
Tem interface visual? E bonita ou funcional? Funciona no celular? O que os usuarios reclamam?

Fase 4 Consolidacao — Debitos

O que esta quebrado, desatualizado ou faltando?
Liste 3 coisas que voce sabe que precisam melhorar. Classifique: qual e urgente, qual e importante, qual pode esperar?

O Que Voce Acabou de Fazer

Voce executou as 4 primeiras fases do Brownfield Discovery — mentalmente. No AIOS, agentes de IA fazem isso automaticamente, em paralelo, e geram documentos completos. Mas o raciocinio e o mesmo: diagnosticar antes de mexer.
