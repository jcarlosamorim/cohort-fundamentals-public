O Problema

A IA Nao Le Sua Mente

Sem PRD, voce esta pedindo pro Claude adivinhar o que voce quer. E adivinhacao gera retrabalho.

Sem PRD
voce: Faz um app de prospeccao
 
claude: OK, vou criar...
  // inventa tudo na hora
  // sem perguntar nada
  // sem contexto do negocio
 
  ✗ app generico
  ✗ sem integracao
  ✗ sem dados reais
  ✗ retrabalho garantido
Com PRD
voce: @pm Preciso de um sistema de prospeccao usando Apify
 
@pm (Morgan): Seguindo template PRD...
  → 15 perguntas estruturadas
  → ICP definido
  → Stack validada
 
  ✓ PRD com 47 decisoes documentadas
  ✓ Scope IN/OUT definido
  ✓ NFRs especificados
  ✓ Zero adivinhacao
A Conta
30 minutos fazendo PRD com o @pm evitam 3 dias refazendo codigo. A IA e poderosa, mas sem direcao ela inventa. Com PRD, ela executa.

O Alerta

5 Projetos Que Morreram Sem PRD

Nao e teoria. E o que acontece quando voce pula a fase de planejamento.

1
“Fiz um app e ninguem usou”
Nao definiu persona/ICP. Construiu para um publico que nao existe. O PRD pergunta PARA QUEM antes de perguntar O QUE.
2
“O Claude inventou features que eu nao pedi”
Sem Scope IN/OUT. A IA nao sabe o que NAO fazer a menos que voce diga. O PRD define limites claros.
3
“Gastei 3 dias e tive que refazer tudo”
Sem architecture decision. Escolheu a stack errada, o banco errado, a estrutura errada. O PRD alimenta a arquitetura ANTES do codigo.
4
“Funciona no meu PC mas nao em producao”
Sem NFRs definidos. Performance, seguranca, escalabilidade — nada foi pensado. O PRD documenta requisitos nao-funcionais que salvam o deploy.
5
“O codigo ficou uma bagunca”
Sem stories estruturadas. Tudo virou uma massa de codigo sem separacao. O PRD gera stories organizadas que o @dev executa uma por vez, com clareza.
A Regra de Ouro
Nenhum desses 5 problemas e tecnico. Todos sao problemas de planejamento. A cadeia PRD → Architecture → Stories → Code existe exatamente pra impedir que isso aconteca com voce.
