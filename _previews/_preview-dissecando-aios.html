🌉 A Ponte: .claude/ O que conecta o Claude Code ao AIOS
Antes de entrar no .aios-core/, existe uma pasta que voce precisa conhecer: a .claude/. Ela fica na raiz do projeto e e o que faz o Claude Code "enxergar" o AIOS. Sem ela, o Claude Code nao saberia que existem agentes, regras ou comandos. E a ponte entre a ferramenta e o framework.
📑
CLAUDE.md
O Arquivo que o Claude Le Primeiro
Quando o Claude Code abre seu projeto, a primeira coisa que ele le e este arquivo. Contém as instrucoes gerais: padroes de codigo, como usar agentes (@agent), como executar comandos (*), convencoes de commit, estrutura do projeto. E o manual de operacao que o Claude segue.
/
commands/
Slash Commands — ~97 comandos de squads
Cada pasta aqui vira um slash command no Claude Code. Quando voce digita /AIOS:agents:pm ou /CopywriterOS:tasks:create-sales-page, o arquivo vem daqui. Sao ~97 comandos que ativam agentes e tasks de todos os squads instalados.
~97 comandos AIOS, CopywriterOS, Hormozi, Design...
📏
rules/
Regras Automaticas — 8 arquivos de lei
Regras que o Claude Code carrega automaticamente em toda sessao. Definem: quem pode fazer push (agent-authority.md), como usar MCPs (mcp-usage.md), ciclo de vida de stories (story-lifecycle.md), prioridade de busca (search-priority.md). O Claude obedece sem voce precisar repetir.
agent-authority.md story-lifecycle.md workflow-execution.md mcp-usage.md credentials.md +3 mais

💡
A Relacao: .claude/ ↔ .aios-core/
Pense assim: .claude/ e o painel de controle do piloto (o que voce ve e interage). .aios-core/ e o motor do aviao (o que faz tudo funcionar). O CLAUDE.md diz ao Claude "use o .aios-core/". Os commands/ criam atalhos para ativar agentes. As rules/ garantem que as leis da constitution.md sejam seguidas. Um sem o outro nao funciona.
⚖️ As Leis O que rege tudo
📜
constitution.md
A Constituicao do AIOS
As leis fundamentais que todos os agentes devem seguir. Define regras como: "Nenhum agente pode fazer git push exceto @devops", "Toda criacao deve consultar o IDS antes", "Tasks com elicit=true exigem interacao com o usuario". E o documento que garante governanca — sem ele, agentes fariam o que quisessem.
⚙️
core-config.yaml
Configuracao Central
O painel de controle de todo o framework. Define qual modelo usar, quais agentes estao ativos, limites de iteracao, configuracoes de CodeRabbit, permissoes, e integracao com ferramentas externas. Muda o comportamento de tudo sem mexer em codigo.
⚙️ O Motor O que faz tudo funcionar
🧠
core/
O Cerebro do Framework — 24 modulos
O motor que faz tudo rodar. Contém os modulos de orquestracao (quem chama quem), sessao (memoria da conversa), registry (catalogo de componentes), quality-gates (verificacoes automaticas), permissoes, execucao, e mais. Voce nao mexe aqui — ele trabalha nos bastidores.
orchestration/ (35 itens) registry/ session/ memory/ quality-gates/ execution/ ids/
🔌
index.js / index.esm.js
Pontos de Entrada
A "porta de entrada" do framework. Quando o Claude Code carrega o .aios-core/, e por aqui que tudo comeca. Um para CommonJS, outro para ES Modules.

🧠 A Inteligencia O que torna o AIOS “esperto”
🔮
workflow-intelligence/
Aprendizado de Padroes
O sistema que aprende com o uso. Detecta padroes nos workflows executados, sugere otimizacoes, e melhora o routing de agentes com o tempo. Contém engine de decisao, modulos de aprendizado, e testes.
engine/ learning/ (10 modulos) registry/ 7 testes
❓
elicitation/
Perguntas Estruturadas
Tres modulos que definem como os agentes fazem perguntas. Quando o @pm te entrevista para criar um PRD, nao sao perguntas aleatorias — e um framework de elicitacao com sequencia, validacao e completude.
agent-elicitation.js task-elicitation.js workflow-elicitation.js

schemas/
Validacao de Formato
JSON Schemas que definem o formato correto de cada componente. Quando voce cria um agente, um task ou um squad, o schema valida se a estrutura esta certa antes de salvar. Previne erros de formato.
agent-v3-schema.json task-v3-schema.json squad-schema.json
